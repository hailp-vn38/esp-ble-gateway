## PHASE V4-10 — Cleanup + Hardening

### Goal

Remove legacy `device_type` / `device_capabilities` code paths and harden the v4 architecture with validation and safety improvements.

---

### Part A: Cleanup

**A1. Remove `list_device_capabilities` command + MCP tool + `device_command` tool**

The dispatcher command `cmd_list_device_capabilities()` and its MCP tool registration are redundant now that the web API has `/api/devices/schema`. The `device_command` generic tool is also legacy.

- `gateway_commands.c`: Remove `cmd_list_device_capabilities()` (lines 288-427) and its registration (lines 436-437)
- `mcp_registry.c`: Remove `list_device_capabilities` and `device_command` from `MCP_STATIC_TOOLS[]`, remove `CONFIG_MCP_EXPOSE_FULL_CAPABILITY_TOOL` and `CONFIG_MCP_KEEP_GENERIC_DEVICE_COMMAND` guards
- `test_command_dispatcher.c`: Remove `list_device_capabilities` assertion

**A2. Update stale README documentation**

- `README.md`: Remove `list_device_capabilities` ref (line 184), `device_capabilities` component ref (line 274)
- `command_dispatcher/README.md`: Fix stale `gw_message_t` struct (line 68 shows `device_type`), fix `edit_device` doc (line 203), remove `list_device_capabilities` row (line 206)
- `docs/MCP_API.md`: Remove/update `list_device_capabilities` refs (lines 318, 485), `device_capabilities_validate_command` (line 452)

**A3. Keep (intentional legacy code — do NOT remove)**

- `device_store_migration.c`: v1/v2 NVS migration loaders
- `schema_cleanup_legacy_caps()`: one-time NVS cleanup
- `cbor_codec.c` comment about reserved key 7
- `test_cbor_codec.c` negative test for device_type

---

### Part B: Hardening

**B1. [HIGH] Validate `feature_total` in `handle_begin()`**

`device_schema.c:382` — `handle_begin()` validates `total > DEVICE_SCHEMA_MAX_TOOLS` but does NOT validate `feature_total`. A malicious device could send `feature_total = 65535` causing OOB write in `staging.features[]`.

→ Add `message->feature_total > DEVICE_SCHEMA_MAX_FEATURES` to the guard.

**B2. [MEDIUM] Add `device_state_forget()` to delete flow**

`cmd_delete_device()` never calls `device_state_forget()`, leaking stale state entries.

→ Add `device_state_forget(msg->device_id)` after schema forget. Add `device_state` to `command_dispatcher/CMakeLists.txt` REQUIRES.

**B3. [MEDIUM] Add dirty retry trigger in mcp_tool_exposure**

When `mcp_tool_exposure_forget_device()` fails to enqueue `WORKER_EVENT_DEVICE_REVOKE`, it sets `s_dirty = true` but nothing ever posts `WORKER_EVENT_DIRTY_RETRY`.

→ After setting `s_dirty`, attempt to enqueue `WORKER_EVENT_DIRTY_RETRY` non-blocking. If that also fails, the next `CAP_COMMITTED` event will retry.

**B4. [LOW] Log unknown CBOR map keys**

Unknown CBOR keys are silently ignored. Adding debug-level logging improves debuggability.

→ After `QCBORDecode_ExitMap()`, walk remaining items with `QCBORDecode_GetNext()` and log unexpected keys.
