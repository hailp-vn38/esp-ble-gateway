# UI Feature Modernization — Implementation Plan

## Tổng quan

Refactor phần **Features** trong Device Detail UI: tách presentation logic ra `feature_ui.js` mới, tự nhóm feature theo semantic, renderer tự chọn theo type, incremental realtime update, và command authoritative state.

---

## Phase UI-0 — Presentation Foundation

**Tạo `feature_ui.js` với presentation registry, group resolution, numeric helpers.**

### Files
- `www_src/dashboard/js/features/feature_ui.js` — **New**
- `www_src/dashboard/shell.html` — thêm `<!-- @js features/feature_ui.js -->` trước `devices.js`

### Chi tiết

**A. Helpers cơ bản trong `featureUi` singleton:**
- `featureKey(feature)` → `"feature_id:property_id"`
- `valueKind(feature)` → `'bool'` | `'int'` | `'none'` (chuẩn hóa từ `feature.value_type` số và `semantic?.value_type` string)
- `scaleOf(feature)` → `10^decimals`
- `rawToDisplay(feature, raw)` / `displayToRaw(feature, value)` — chuyển đổi raw↔display
- `formatNumeric(feature, raw)` → `"25.1 °C"`

**B. Presentation registry:** Key = `semantic.name:semantic.property`

| Key | Group | Renderer | Icon |
|---|---|---|---|
| `relay:on_off` | controls | toggle | power |
| `outlet:on_off` | controls | toggle | plugs |
| `light:on_off` | controls | toggle | lightbulb |
| `light:level` | controls | range | lightbulb |
| `fan:percent_setting` | controls | range | devices |
| `temperature:temperature` | environment | metric | thermometer |
| `humidity:humidity` | environment | metric | info |
| `contact:contact` | environment | contact | info |
| `value:value` | settings | generic-number | info |

**C. Resolution:** `presentationKey()` → `resolvePresentation()` (with fallback theo valueKind + writable) → `groupFeatures()` → `{ controls, environment, settings, other }`

**D. Stub render functions** (triển khai ở phase sau)

### Checklist
- [ ] feature_ui.js load trước devices.js
- [ ] Không có API call nào trong featureUi
- [ ] Presentation fallback đúng cho unknown types
- [ ] Helpers hoạt động đúng

**Icons chỉ dùng subset có sẵn:** ph-power, ph-plugs, ph-lightbulb, ph-thermometer, ph-devices, ph-info

### Checklist

## Phase UI-2 — Specialized Renderers

**Triển khai 5 renderer: toggle, range, metric, contact, generic-number.**

### Files
- `www_src/dashboard/js/features/feature_ui.js` — implement renderers
- `www_src/dashboard/js/features/devices.js` — refactor calls sang `featureUi`

### Chi tiết

**Toggle** (`_renderToggle`): `role="switch"` + `aria-checked`, reuse `.settings-switch` pattern từ shell.html. States: OFF (gray), ON (brand), PENDING (disabled+spinner), OFFLINE (disabled).

**Range** (`_renderRange`): Slider + value label. `oninput` → preview only, `onchange` → send once. Guard: `data-user-editing` attribute.

**Metric** (`_renderMetric`): Value as visual focus. Không render "No write tool".

**Contact** (`_renderContact`): false→Closed (green), true→Open (amber). Không dùng ON/OFF.

**Generic number** (`_renderGenericNumber`): Slider + numeric input + Apply. Validation trên raw integer.

**Refactor `devices.js`:** `renderFeatures()` gọi `featureUi.renderFeatures()`. Chuyển numeric helpers sang featureUi.

### Checklist
- [ ] relay/plug/light → toggle, fan/dimmer → range, temp/humidity → metric, contact → contact, generic → generic-number
- [ ] Slider preview on input, send on change
- [ ] Read-only KHÔNG hiển thị "No write tool"
- [ ] devices.js không còn card-specific markup

## Phase UI-3 — Incremental Realtime Update

**WebSocket state event chỉ update 1 card, không rebuild toàn bộ.**

### Files
- `www_src/dashboard/js/features/feature_ui.js` — card map, `updateFeatureState()`, `updateConnectionState()`
- `www_src/dashboard/js/features/devices.js` — gọi incremental update

### Chi tiết

**Card map:** `cardByFeatureKey: new Map()`. Clear khi full render.

**`updateFeatureState(feature, device)`:** Lookup card by key → switch trên presentation.renderer → update DOM element cụ thể.

**`_handleFeatureStateEvent()`:** Thay `this.renderFeatures(...)` bằng `featureUi.updateFeatureState(feature, device)`.

**`_applyConnectionEvent()`:** Thay `this.renderFeatures(...)` bằng `featureUi.updateConnectionState(features, device)`.

**`_reconcileFeatureCacheAfterSnapshot()`:** Thu thập changed features, update từng card.

**Slider guard:** `data-user-editing` attribute, WS update skip khi user đang drag.

### Checklist
- [ ] Feature.state update chỉ thay đổi 1 card DOM
- [ ] Slider KHÔNG nhảy khi user đang drag
- [ ] Offline/reconnect update đúng

## Phase UI-4 — Command States

**Pending state, authoritative ACK từ HTTP response, WS reconcile.**

### Files
- `web_command_api.c` — thêm `feature_state` vào JSON response (từ `result->has_feature_value_bool/int`)
- `www_src/dashboard/js/core/api.js` — giữ raw response object
- `www_src/dashboard/js/features/devices.js` — `sendFeatureCommand()`, apply authoritative state
- `www_src/dashboard/js/features/feature_ui.js` — `setPending()`

### Chi tiết

**Backend:** `device_command_completion()` — nếu `result->has_feature_value_bool/int`, thêm `"feature_state": { "value_type": "bool"|"int", "value_bool"|"value_int": ... }` vào response JSON.

**Frontend:** `sendFeatureCommand()` → setPending(true) → sendCommand → apply feature_state → setPending(false).

**State sync order:** 1. HTTP authoritative → 2. WebSocket realtime → 3. REST snapshot → 4. Local preview only.

### Checklist
- [ ] `/api/command` response chứa `feature_state`
- [ ] UI apply authoritative state
- [ ] Pending state visible
- [ ] Command clamp đúng khi WS degraded
