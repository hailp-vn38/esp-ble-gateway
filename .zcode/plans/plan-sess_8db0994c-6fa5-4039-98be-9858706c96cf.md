## Phase 6: Introduce Shared MCP Semantic-Control Helper

### Goal
Extract shared resolver, feature info, and hint serialization from `mcp_device_control.c` into a reusable `mcp_semantic_control` module, so both `device_control` and future typed `list_devices` (Phase 7) reuse one implementation.

### What already exists
- `mcp_semantic_control_get_hints()` in `mcp_tool_exposure` — already produces filtered `mcp_control_hint_t` arrays with exposure/policy checks
- `mcp_policy_check_feature_control()` in `mcp_policy.c` — already checks write permissions
- **Duplication to eliminate**: hint→cJSON serialization loop (identical in `gateway_commands.c:303-326` and `web_device_api.c:144-165`)

### Files to Create

1. **`components/mcp_endpoint/mcp_semantic_control.h`** — private header with:
   - `mcp_sem_resolve_status_t` enum (OK, NOT_FOUND, AMBIGUOUS, INVALID)
   - `mcp_sem_resolve_device(arg, out, out_len)` — extract from static `resolve_device()` in mcp_device_control.c
   - `mcp_sem_resolve_feature(schema, arg, out)` — extract from static `resolve_feature()` in mcp_device_control.c
   - `mcp_sem_serialize_feature(array, schema, feature)` — extract from static `add_feature()` in mcp_device_control.c

2. **`components/mcp_endpoint/mcp_semantic_control.c`** — implementation of above functions

3. **`components/mcp_endpoint/test/test_mcp_semantic_control.c`** — unit tests

### Resolver rules (unchanged from current behavior)
- device_id exact preferred, unique name fallback, ambiguous → fail closed
- feature_id exact preferred, semantic_name fallback, ambiguous → fail closed
